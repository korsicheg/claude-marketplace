# Glossary — clean-code-typescript

**3 R's of software architecture** — code is good insofar as it is Readable, Reusable, Refactorable (Ch 1)
**Accessor** — a `get`/`set` member that looks like a property but runs code (Ch 4)
**Argument budget** — ≤2 ideal, 3 avoided, more consolidated into an options object (Ch 3)
**`as const` (const assertion)** — freezes a literal deeply, including one a function returns (Ch 4)
**`async` function** — a function that may `await`; always returns a promise (Ch 8)
**`await`** — pauses the enclosing async function until a promise settles (Ch 8)
**Banner comment** — see *positional marker* (Ch 11)
**Callback hell** — the nesting pyramid produced by callback composition (Ch 8)
**Cohesion** — how related a class's members are; measured by whether all fields are used by all methods (Ch 5)
**Combinatorial explosion** — the test-case blowup from many parameters; the reason for the argument budget (Ch 3)
**Comment as apology** — a comment admits the code failed to express itself (Ch 11)
**Commented-out code** — disabled code left in the file; delete it, git has it (Ch 11)
**Coupling** — dependency between classes; low coupling means changes don't propagate (Ch 5)
**Coverage (statements + branches)** — the metric to target at 100% before shipping or refactoring (Ch 7)
**Dead code** — uncalled or unreachable code; "just as bad as duplicate code" (Ch 3)
**Default argument** — `count: number = 10`; replaces short circuiting and puts the default in the signature (Ch 2)
**Dependency Injection (DI)** — supplying a dependency from outside, usually via constructor; the usual DIP mechanism, but **not the same concept** (Ch 6)
**Dependency Inversion Principle (DIP)** — high-level and low-level modules both depend on abstractions; abstractions don't depend on details (Ch 6)
**Discriminated union** — a union narrowed by a literal field, e.g. `isError: true | false` (Ch 9)
**Encapsulated conditional** — a boolean expression given a name by extracting it into a predicate (Ch 3)
**`enum`** — use when you care that values are *distinct*, not what they literally are (Ch 2)
**`Error`** — the type to throw and reject with; carries `message` and, crucially, `stack` (Ch 9)
**Explanatory variable** — a local (often from destructuring) introduced solely to name a value (Ch 2)
**Fail-fast** — `Promise.all` rejects with the *first* rejection and doesn't cancel the rest (Ch 8)
**`Failable<R, E>`** — `Result<R> | Failure<E>`; failure as a typed return value instead of a throw (Ch 9)
**Fat interface** — one interface bundling capabilities not every implementer has; ISP's target (Ch 6)
**F.I.R.S.T.** — Fast, Independent, Repeatable, Self-Validating, Timely: the properties of clean tests (Ch 7)
**Flag argument** — a boolean parameter selecting a code path; proof the function does two things (Ch 3)
**Fluent interface / method chaining** — mutators returning `this` so calls compose (Ch 5)
**Folding region** — an IDE feature that collapses blocks, making section banners redundant (Ch 11)
**Generator** — `function*` + `yield`, consumed with `for-of`; a lazy on-demand stream (Ch 3)
**"has-a" vs "is-a"** — the test that decides composition vs inheritance (Ch 5)
**`import type`** — a type-only import, erased at runtime, which is how it breaks dependency cycles (Ch 10)
**Interface Segregation Principle (ISP)** — clients shouldn't depend on interfaces they don't use (Ch 6)
**Intersection type** — `A & B`; expressible only with `type` (Ch 4)
**IoC container** — infrastructure that wires implementations to abstractions; InversifyJS in TS (Ch 6)
**Journal comment** — a dated change log in source; `git log` replaces it (Ch 11)
**Liskov Substitution Principle (LSP)** — a subtype must be substitutable for its supertype without breaking callers (Ch 6)
**Magic number / magic string** — an unnamed literal whose meaning lives only in the author's head (Ch 2)
**Mapped type** — a type transforming each property of another; `Readonly<T>` is the built-in one (Ch 4)
**Maximally cohesive** — every field used by every method; an ideal the source calls "not always advisable" (Ch 5)
**Mental mapping** — the reader-side cost of translating a short name into its concept (Ch 2)
**Named constant** — a `SNAKE_CASE` binding giving a literal a searchable name (Ch 2)
**Negative conditional** — `isEmailNotUsed(x)`; prefer `!isEmailUsed(x)` (Ch 3)
**Newspaper rule** — keep caller directly above callee; read top-to-bottom, general to specific (Ch 10)
**Open/Closed Principle (OCP)** — open for extension, closed for modification: add behavior without editing existing code (Ch 6)
**Options object** — a single destructured object parameter named via a `type` alias (Ch 3)
**Parameter property** — an access modifier on a constructor parameter; declares and assigns in one line (Ch 4)
**Path alias** — `@services/UserService` via `baseUrl` + `paths` in tsconfig; kills `../../../` chains (Ch 10)
**Positional marker** — `////// public methods //////` banners; noise, replaced by names and folding (Ch 11)
**Prettier** — the opinionated formatter; `eslint-config-prettier` reconciles it with ESLint (Ch 10)
**`Promise.all`** — runs independent tasks in parallel; fails fast on the first rejection (Ch 8)
**`Promise.race`** — first settled wins; the timeout primitive (Ch 8)
**Promisify** — mechanically convert a callback API to promises (`util.promisify`, `pify`, `es6-promisify`) (Ch 8)
**Pure function** — takes values in, returns values out, touches nothing else (Ch 3)
**`readonly`** — marks one property non-reassignable; compile-time only (Ch 4)
**`Readonly<T>`** — mapped type marking every property of `T` readonly (Ch 4)
**`ReadonlyArray<T>`** / **`readonly T[]`** — an array type without `push`/`fill`; `concat`/`slice` remain (Ch 4)
**Responsibility** — a single reason a class would have to change; the unit class size is measured in (Ch 5)
**Role interface** — a small interface named for one capability (`Printer`, `Fax`, `Scanner`) (Ch 6)
**Self-documenting code** — code whose names carry the intent a comment would have (Ch 11)
**Self-validating** — a test answers Passed or Failed with no human reading logs (Ch 7)
**Side effect** — anything a function does besides take values and return values (Ch 3)
**Single concept per test** — SRP for an `it()` block; one assert (Ch 7)
**Single Responsibility Principle (SRP)** — never more than one reason for a class to change (Ch 5, Ch 6)
**Square–Rectangle problem** — the classic LSP violation; `.setWidth(4).setHeight(5).getArea()` returns 25, not 20 (Ch 6)
**Substitutability** — the property LSP names: swapping in a subtype changes nothing callers rely on (Ch 6)
**Swallowed error** — a `catch` that does nothing, or only `console.log`s (Ch 9)
**`this` return type** — TypeScript's polymorphic self-type; keeps chains correct in subclasses (Ch 5)
**Three Laws of TDD** — no production code without a failing test; no more test than suffices to fail (**compilation failures count**); no more code than passes that one test (Ch 7)
**`// TODO`** — the one endorsed comment form; findable by IDEs, and not an excuse for bad code (Ch 11)
**Touchstone** — a reference standard for comparison, not a gate; how to use these rules (Ch 1)
**`type` vs `interface`** — `type` for unions/intersections, `interface` for `extends`/`implements`; no strict rule beyond that (Ch 4)
**Union type** — `A | B`; expressible only with `type` (Ch 4)
**Unneeded context** — name segments already implied by the enclosing type; test at the *use site* (Ch 2)
**Wet-clay model** — code starts as a first draft and is shaped in review; "beat up the code instead" (Ch 1)
