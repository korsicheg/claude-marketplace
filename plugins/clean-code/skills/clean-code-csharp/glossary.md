# Glossary — clean-code-csharp

**3 Rs (readable, reusable, refactorable)** — the guide's stated quality standard (Ch 1)
**AAA (Arrange–Act–Assert)** — test layout: set up, perform one action, verify; "forces" clean single-concept tests (Ch 11)
**Abstraction (DRY sense)** — one function, class or module that handles every variant of near-duplicate code (Ch 10)
**Allman braces** — every `{` on its own line; `csharp_new_line_before_open_brace = all` (Ch 14)
**Anonymous type** — `new { Name = …, Age = … }`; compiler-named, so neither searchable nor reusable (Ch 3)
**Async all the way** — "Don't mix blocking and async code"; callers of async code are async too (Ch 12)
**`async void`** — an async method nobody can await; only for event handlers (Ch 12)
**`AsyncLazy<T>` / `AsyncCollection<T>`** — non-BCL types from Nito.AsyncEx named in the source's async table (Ch 12)
**Auto-property** — `{ get; set; }`; the compiler supplies the backing field (Ch 2, Ch 7)
**Bad abstraction** — a merge of things that don't vary together; "can be worse than duplicate code" (Ch 10)
**Branch coverage** — share of decision outcomes executed by tests; the source targets 100% (Ch 11)
**Collection expression** — `["friday", "saturday"]`; C# 12 literal for arrays, lists and spans (Ch 1, Ch 3, Ch 10)
**Composition** — holding another object as a member instead of inheriting from it (Ch 8)
**Compute-bound** — work limited by the CPU; `await` doesn't help, a dedicated thread does (Ch 12)
**`ConfigureAwait(false)`** — resume without the captured context; "when you can" (Ch 12)
**Custom exception** — an `Exception` subclass adding context, constructed with the original as inner exception (Ch 13)
**Dead code** — code nothing calls; delete it, version history keeps it (Ch 4)
**Default argument** — `string breweryName = "Hipster Brew Co."`; a compile-time-constant default in the signature (Ch 3)
**Dependency Injection (DI)** — supplying collaborators from outside, usually through the constructor; DIP's usual .NET mechanism (Ch 9)
**Dependency Inversion Principle (DIP)** — high- and low-level modules both depend on abstractions; abstractions don't depend on details (Ch 9)
**Domain name** — a name from programmers' shared vocabulary (pattern and algorithm names) (Ch 2)
**DRY** — Don't Repeat Yourself; one place to change each piece of logic (Ch 10)
**`dynamic`** — opts a value out of compile-time type checking (Ch 5)
**`.editorconfig`** — a root-level settings file for formatting, style preferences and naming rules (Ch 14)
**Encapsulated conditional** — a named predicate (`IsPublished()`) hiding a raw comparison (Ch 5)
**Explanatory variable** — a name given to part of an opaque expression, e.g. a named regex group (Ch 3)
**Extension method** — a `static` method with a `this` first parameter, callable like an instance method (Ch 8)
**`[Fact]`** — xUnit attribute marking a parameterless test (Ch 11)
**Fat interface** — one interface bundling capabilities not every implementer has (Ch 9)
**Flag parameter** — a `bool` argument that selects a code path; split into two methods (Ch 4)
**Fluent interface / method chaining** — each call returns an object the next call can be made on (Ch 8)
**Get-only property** — `{ get; }`; set only in a constructor or initializer (Ch 7)
**Global function / global state** — reachable from anywhere without being passed in; hides dependencies (Ch 6)
**Guard clause** — an early `return` or `throw` for a precondition, so the main path needn't nest (Ch 3)
**Hidden dependency** — a collaborator used but not declared in a constructor or signature (Ch 6)
**Hungarian notation** — type prefixes in names (`iCounter`, `strFullName`, `pDay`) (Ch 2)
**I/O-bound** — work that waits on network, disk or database; what `async`/`await` is for (Ch 12)
**Inner exception** — the original exception carried inside a new one via `InnerException` (Ch 13)
**Interface inheritance** — `interface IEmployee : IFeedable, IWorkable`; composing role interfaces (Ch 9)
**Interface Segregation Principle (ISP)** — "Clients should not be forced to depend upon interfaces that they do not use" (Ch 9)
**IoC container** — builds objects and supplies their dependencies; "resolve from IOC" (Ch 6, Ch 9)
**Journal comment** — a dated changelog in a comment; use `git log` (Ch 15)
**Level of abstraction** — the altitude of a statement: orchestration vs mechanics (Ch 4)
**Liskov Substitution Principle (LSP)** — base and child "can be used interchangeably without getting incorrect results" (Ch 9)
**`LongRunning`** — `TaskCreationOptions` hint for a dedicated thread for compute-bound work (Ch 12)
**Magic string** — a behaviour-affecting literal "specified directly within application code" (Ch 3)
**Mental mapping** — translating a short name (`li`) back into its concept (Ch 3)
**Named arguments** — `new MenuConfig(Title: "Foo", …)`; labelled values at the call site (Ch 4)
**Named capture group** — `(?<city>…)` in .NET regex, read via `Groups["city"]` (Ch 3)
**Negative conditional** — a predicate named for an absence (`IsDOMNodeNotPresent`) (Ch 5)
**Newspaper order** — callers above callees, read top-down (Ch 4)
**Nullable reference annotation** — `EmployeeTaxData?`; the value may legitimately be `null` (Ch 8)
**Open/Closed Principle (OCP)** — "open for extension, but closed for modification" (Ch 9)
**Options pattern** — typed settings delivered as `IOptions<T>` (Ch 6)
**Parameter object** — one type bundling related arguments; in C#, a positional `record` (Ch 4)
**Pattern matching (type pattern)** — `x is Car car`: test and bind in one step (Ch 5, Ch 14)
**Polymorphism** — one call dispatched to the right implementation by the object's type (Ch 5)
**Port artifact** — JavaScript or PHP syntax left in a C# example (Ch 1)
**Positional marker** — a banner comment or `#region` labelling a section of a file (Ch 15)
**Primary constructor** — `class Employee(string name)`; C# 12 parameters in scope across the class (Ch 1, Ch 7)
**Property** — a member with `get`/`set` accessors that reads like a field but runs code (Ch 7)
**Reason to change** — a source of change requests; SRP's unit of responsibility (Ch 9)
**`record`** — a type with value equality and concise positional syntax (C# 9) (Ch 4, Ch 8)
**`#region`** — a C# directive for a collapsible block; the source treats it as a positional marker (Ch 15)
**Role interface** — a small interface for one capability (`IWorkable`) (Ch 9)
**Searchable name** — a name or type that grep and Find All References can locate (Ch 3)
**Severity (`.editorconfig`)** — `none`/`suggestion`/`warning`/`error`; how strongly a preference is applied (Ch 14)
**Side effect** — anything a function does besides taking values in and returning values out (Ch 4)
**Single concept per test** — one behaviour per test, named for that behaviour (Ch 11)
**Single Responsibility Principle (SRP)** — "There should never be more than one reason for a class to change" (Ch 9)
**Singleton pattern** — a class that creates and hides its one instance behind a static accessor; an anti-pattern here (Ch 6)
**SOLID** — Feathers' mnemonic for Martin's five principles (Ch 9)
**Square–Rectangle problem** — the textbook LSP violation (Ch 9)
**Stack trace** — the call path to a throw; `throw;` keeps it, `throw ex;` resets it (Ch 13)
**Statement coverage** — share of statements executed by tests (Ch 11)
**Swallowed exception** — caught and ignored (Ch 13)
**TAP** — the Task-based Asynchronous Pattern, .NET's convention for async APIs (Ch 12)
**`throw;`** — rethrow the current exception unchanged (Ch 13)
**Unneeded context** — repeating the type's name in its own members (`Car.CarMake`) (Ch 3)
