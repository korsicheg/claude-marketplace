# Glossary — clean-code-javascript

**Abstraction level** — how far a statement sits from the domain; mixing levels in one function is a split signal (Ch 3)
**async function** — a function that returns a promise and may `await` inside; enables imperative async code (Ch 8)
**await** — suspends until a promise settles, yielding its value to an ordinary variable (Ch 8)
**Callback hell / pyramid of doom** — rightward drift from nested callbacks, each with its own error branch (Ch 8)
**Combinatorial explosion** — test cases multiplying with each extra function argument; the reason for the ≤2 argument rule (Ch 3)
**Comment as apology** — the framing that a comment concedes the code failed to explain itself (Ch 11)
**Commented-out code** — dead code in disguise; delete it, `git` has it (Ch 11)
**Composition** — modeling a relationship by holding an instance rather than extending a type; the default over inheritance (Ch 5)
**Conceptual cohesion** — everything in a class belonging to the same idea; what SRP protects (Ch 6)
**Consistent API** — every type in a position exposes the same method, removing the need to type-check (Ch 3, Ch 6)
**Coupling** — a module's dependence on another's concrete details; "a very bad development pattern because it makes your code hard to refactor" (Ch 6)
**Coverage (statement and branch)** — proportion of statements *and* conditional branches exercised by the suite (Ch 7)
**Dead code** — unreferenced code kept "just in case"; "just as bad as duplicate code" (Ch 3)
**Default parameter** — an ES6 signature default; fires on `undefined` **only**, unlike `||` (Ch 2)
**Dependency Injection (DI)** — constructing collaborators externally and passing them in; the usual mechanism for DIP (Ch 6)
**Dependency Inversion Principle (DIP)** — high-level modules and low-level modules both depend on abstractions; details depend on abstractions (Ch 6)
**Duck typing** — if it has the method, it qualifies; JavaScript's stand-in for interfaces (Ch 6)
**Encapsulation** — callers depend on an accessor contract, not on a field's existence or shape (Ch 4)
**Explanatory variable** — a named const introduced purely to give a subexpression a meaning (Ch 2)
**Factory function** — a plain function returning an object of methods (`makeBankAccount`), closing over private state (Ch 4)
**Fat interface** — a required settings object demanding options most clients never use; what ISP forbids (Ch 6)
**Flag argument** — a boolean parameter selecting a branch; a direct admission the function does two things (Ch 3)
**Fluent interface** — the API style method chaining produces, as in jQuery and Lodash (Ch 5)
**Getter / setter** — a method mediating read/write access to internal state; the only guaranteed validation point (Ch 4)
**Global pollution** — adding to `Array.prototype` or another built-in, risking library collisions (Ch 3)
**Guidelines, not laws** — "Not every principle herein has to be strictly followed, and even fewer will be universally agreed upon" (Ch 1)
**Implicit contract** — the methods/properties one object expects another to expose; JS's interface substitute (Ch 6)
**Interface Segregation Principle (ISP)** — "Clients should not be forced to depend upon interfaces that they do not use" (Ch 6)
**is-a vs has-a** — the relationship test deciding inheritance vs composition (Human→Animal vs User→UserDetails) (Ch 5)
**Journal comment** — a dated changelog block inside source; replaced by `git log` (Ch 11)
**Lazy loading** — deferring a property's computation or fetch until its getter is first called (Ch 4)
**Level of abstraction** — see *Abstraction level* (Ch 3)
**Liskov Substitution Principle (LSP)** — subtypes must be substitutable for base types without altering correctness (Ch 6)
**Magic number** — an unnamed numeric literal whose meaning lives only in the author's head (Ch 2)
**Mental mapping** — forcing the reader to remember that `l` means `location`; "Explicit is better than implicit" (Ch 2)
**Method chaining** — returning `this` from methods so calls compose into one expression (Ch 5)
**Newspaper rule** — keep callers vertically close to callees; read code top-to-bottom, summary before detail (Ch 10)
**Open/Closed Principle (OCP)** — "open for extension, but closed for modification" (Bertrand Meyer) (Ch 6)
**Positional marker** — a `////////` banner faking structure; "they usually just add noise" (Ch 11)
**Promise** — a built-in global type since ES2015/ES6 representing a future value (Ch 8)
**Pronounceable name** — a name you can say aloud unambiguously in a code review (Ch 2)
**Prototype boilerplate** — the ES5 `Object.create` + `prototype.constructor` + `instanceof` ritual ES6 classes replace (Ch 5)
**Pure function** — takes values, returns values, touches nothing else (Ch 3)
**Reason to change** — the SRP unit of responsibility; two reasons means two classes (Ch 6)
**Refactorable** — internals can change without breaking callers; third of the 3 Rs (Ch 1)
**Readable** — a reader who didn't write it can follow its intent without running it; first of the 3 Rs (Ch 1)
**Rejected promise** — the promise-chain equivalent of a throw; ignoring it is the same defect as an empty `catch` (Ch 9)
**Reusable** — callable from a second place without modification; second of the 3 Rs (Ch 1)
**Searchable name** — a name or constant you can grep, as opposed to a bare literal like `86400000` (Ch 2)
**Self-documenting code** — code whose names and structure make intent legible without prose (Ch 11)
**Short-circuiting default** — `x || fallback`, which fires on *every* falsy value, not just `undefined` (Ch 2)
**Side effect** — anything a function does other than take a value in and return a value out (Ch 3)
**Single concept per test** — one `it` block, one behavior, one reason to fail (Ch 7)
**Single Responsibility Principle (SRP)** — "There should never be more than one reason for a class to change" (Ch 6)
**SOLID** — SRP, OCP, LSP, ISP, DIP; in JS the abstractions are implicit contracts, not compiler-checked types (Ch 6)
**Stack trace** — the diagnostic a thrown error hands you for free (Ch 9)
**Stepdown order** — layout where each function appears just above those it calls, descending in abstraction (Ch 10)
**Subtype substitutability** — a child can stand in for its parent without changing correctness; LSP's test (Ch 6)
**Swallowed error** — a caught error producing no action; Ch 9's core anti-pattern
**Test Driven Development (TDD)** — writing the test first; endorsed but explicitly optional (Ch 7)
**The 3 Rs** — readable, reusable, refactorable: the guide's quality test (Ch 1)
**Unneeded context** — repeating the container's name inside its members (`car.carColor`) (Ch 2)
**Vertical proximity** — the line distance between a caller and its callee; keep it near zero (Ch 10)
**Wet-clay model** — every piece of code starts as a first draft; review is the chiselling step (Ch 1)
