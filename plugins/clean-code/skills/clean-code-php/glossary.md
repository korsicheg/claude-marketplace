# Glossary — clean-code-php

**3 Rs (readable, reusable, refactorable)** — the guide's stated quality standard (Ch 1)
**Abstraction** — in this guide, almost always a PHP `interface` that callers depend on (Ch 8, Ch 9)
**Accessor** — a method standing between callers and a property: a getter or an operation like `withdraw()` (Ch 6)
**Bad abstraction** — a merge of things that don't vary together; "can be worse than duplicate code" (Ch 9)
**Bit-flag constant** — a power-of-two `public const` combined with `|`, tested with `&`, toggled with `^=` (Ch 2)
**Builder** — an object for staged configuration; the one context where the guide accepts fluent interfaces (Ch 7)
**Coercive (weak) mode** — PHP's default typing mode, in which numeric strings are converted to match scalar type declarations (Ch 5)
**Composition** — holding a collaborator as a field ("has-a") instead of inheriting from it (Ch 7)
**Constructor injection** — passing collaborators into `__construct()` rather than creating or fetching them inside (Ch 4, Ch 8)
**Dead code** — code with no caller; "just as bad as duplicate code" (Ch 5)
**Decorator** — a wrapper implementing the same interface; fluent `return $this` lets calls escape it (Ch 7)
**Default argument** — a fallback declared in the signature; with a type declaration it rules out `null` (Ch 4)
**Dependency Injection (DI)** — supplying collaborators from outside, as Symfony's container does; how PHP frameworks deliver DIP (Ch 8)
**Dependency Inversion Principle (DIP)** — high- and low-level modules both depend on abstractions; details depend on abstractions (Ch 8)
**DRY** — Don't Repeat Yourself; one place to alter each piece of logic (Ch 9)
**ECS (Easy Coding Standard)** — the Symplify linter the repo runs on the README's PHP blocks (Ch 1)
**Encapsulate conditionals** — moving a condition into a named predicate method (`isPublished()`) (Ch 5)
**Explanatory variable** — a name given to part of an opaque expression, e.g. a regex match (Ch 2)
**Fat interface** — an interface whose members no single implementer needs in full (Ch 8)
**`final` class** — a class that cannot be extended; preferred "whenever possible", provided it implements an interface (Ch 7)
**Flag argument** — a boolean parameter selecting a code path; "this function does more than one thing" (Ch 4)
**Fluent interface** — an API whose methods `return $this` for chaining; avoided outside builders (Ch 7)
**Global function** — a function in the global namespace, e.g. `config()`; risks clashing with other libraries (Ch 4)
**`global` keyword** — imports a global variable into function scope; the guide's side-effect example (Ch 4)
**Guard clause** — an early `return` or `throw` that handles an edge case so the main path stays unindented (Ch 2)
**Identical comparison** — `===` / `!==`; compares type and value (Ch 3)
**Interface inheritance** — `interface Employee extends Feedable, Workable`; PHP interfaces may extend several interfaces (Ch 8)
**Interface Segregation Principle (ISP)** — "Clients should not be forced to depend upon interfaces that they do not use" (Ch 8)
**Jenga effect** — a change in one place collapsing code elsewhere that relied on it; what `private` prevents (Ch 6)
**Level of abstraction** — the altitude of a statement: orchestration vs mechanics; one per function (Ch 4)
**Liskov Substitution Principle (LSP)** — a parent and child class "can be used interchangeably without getting incorrect results" (Ch 8)
**List destructuring** — `[, $city, $zipCode] = $matches;` (PHP 7.1); the "Not bad" rung for regex results (Ch 2)
**Loose comparison** — `==` / `!=`; compares after type juggling, so `'42' == 42` (Ch 3)
**Magic number** — an unexplained literal such as `448` or `4` (Ch 2)
**Mental mapping** — forcing the reader to translate a short name (`$li`) into what it stands for (Ch 2)
**Named subpattern** — `(?<name>…)` in a PCRE pattern, read as `$matches['name']` (Ch 2)
**Near-miss duplication** — copies that differ slightly, the usual form duplication takes (Ch 9)
**Null coalescing operator** — `??`; returns the left operand if set and not `null`, else the right (PHP 7) (Ch 3)
**Open/Closed Principle (OCP)** — "open for extension, but closed for modification" (Bertrand Meyer) (Ch 8)
**Polymorphism** — selecting behaviour by the object's class instead of a conditional (Ch 5, Ch 8)
**Predicate method** — a boolean method named for its question, stated positively (Ch 5)
**`private` by default** — the guide's visibility rule; open to `public`/`protected` only when external classes need access (Ch 6)
**`protected`** — visible to subclasses; "as dangerous as public" for encapsulation (Ch 6)
**PSR-12** — PHP-FIG's extended coding style, one of the rule sets the repo's linter applies (Ch 1)
**Reason to change** — the unit of responsibility SRP counts (Ch 8)
**Searchable name** — a named constant in place of a literal, so it can be grepped (Ch 2)
**Short ternary** — `?:`; falls back when the left side is falsy — not the same as `??` (Ch 3, Ch 4)
**Side effect** — anything other than taking values in and returning values; centralize in "one service" (Ch 4)
**Single Responsibility Principle (SRP)** — "There should never be more than one reason for a class to change" (Ch 8)
**Singleton** — a class managing its own single instance via `getInstance()`; an anti-pattern in this guide (Ch 4)
**SOLID** — Michael Feathers' acronym for five principles named by Robert Martin (Ch 8)
**Strict mode** — `declare(strict_types=1)`; disables scalar coercion for calls from that file; named but not shown by the guide (Ch 5)
**Substitutability** — an implementation usable wherever its declared type is expected, without changing results (Ch 8)
**Type declaration** — a parameter or return type (`int $x`, `: void`, `?string`) enforced by the engine (Ch 4, Ch 5)
**Type juggling** — PHP's implicit conversion between types during comparison and arithmetic (Ch 3)
**Unneeded context** — repeating the class name in its own properties (`Car::$carMake`) (Ch 2)
**Value object** — a small class bundling related values (`Name`, `City`, `Contact`) to cut argument count (Ch 4)
**Vocabulary consistency** — one name per entity: `getUser()`, not `getUserInfo`/`Data`/`Record`/`Profile` (Ch 2)
