# Glossary — clean-code-ruby

**3 Rs (readable, reusable, refactorable)** — the guide's stated quality standard (Ch 1)
**Abstraction level** — the altitude of a statement: orchestration (`tokenize(code)`) vs mechanics (`code.split(' ')`); one per method (Ch 3)
**Adapter** — a class wrapping one transport behind a shared message, e.g. `AjaxAdapter#request(url)` (Ch 7)
**`attr_accessor`** — class macro generating a trivial reader and writer; for data-like objects, and "in some situations … a code smell" (Ch 5, Ch 6)
**`attr_reader`** — class macro generating a reader only; used for the adapters' `name` (Ch 5, Ch 7)
**Bad abstraction** — a merge of things that don't vary together; "can be worse than duplicate code" (Ch 4)
**`begin` / `rescue`** — Ruby's try/catch; wrapping code in one claims you have a plan for its failure (Ch 9)
**Block parameter** — the `|location|` in `each do |location|`; a name like any other, and the commonest place for mental mapping (Ch 2)
**Branch coverage** — every side of every conditional exercised by a test; the guide asks for it alongside statement coverage (Ch 8)
**Builder** — an object that accumulates configuration before producing a result; the sanctioned home for method chaining, e.g. ActiveRecord queries (Ch 6)
**Capitalization** — in Ruby, meaningful: a capitalized identifier is a constant; the guide asks for one convention per kind of name (Ch 10)
**Combinatorial explosion** — test cases multiplying with each extra argument; the stated reason for the two-argument limit (Ch 3)
**Commented-out code** — disabled code left in place; delete it, version control keeps it (Ch 11)
**Composition** — modelling "has-a" by holding an instance, e.g. `@tax_data = EmployeeTaxData.new(...)` (Ch 6)
**Consistent API** — one message name across types (`vehicle.move`), so callers never check which type they hold (Ch 4)
**Constant** — a capitalized identifier such as `SECONDS_IN_A_DAY`; the home for magic numbers (Ch 2, Ch 10)
**contracts.ruby** — a gem adding declarative runtime contracts to methods; the guide's option for primitive-value checks (Ch 4)
**Coupling** — dependence of one module on another's details; "makes your code hard to refactor" (Ch 7)
**Coverage tool** — reports which statements and branches tests executed; the guide links Coveralls (Ch 8)
**Data-like object** — an object whose job is to expose data (ActiveRecord model, API response wrapper); where `attr_accessor` fits (Ch 5)
**Dead code** — code nothing calls; "just as bad as duplicate code" (Ch 4)
**Decorator** — a wrapper that adds behaviour; fluent interfaces break it because `self` escapes the wrapper (Ch 6)
**Default argument** — a fallback in the signature, e.g. `brewery_name = 'Hipster Brew Co.'`; applies only when the argument is omitted, never to an explicit `nil` or `false` (Ch 2)
**Dependency injection** — passing a collaborator into `initialize` instead of constructing it there (Ch 7)
**Dependency Inversion Principle (DIP)** — high-level and low-level modules both depend on abstractions; details depend on abstractions (Ch 7)
**Duck typing** — accepting any object that answers the messages you send; why Ruby's interfaces are implicit (Ch 4, Ch 7)
**Duplicate code** — logic in more than one place, so a change needs more than one edit (Ch 4)
**`Enumerable` methods** — `sum`, `select`, `map`, `each_with_object`: block-taking methods that replace accumulator loops (Ch 3)
**Expectation** — one `expect(...).to ...` assertion in RSpec; one per example (Ch 8)
**Explanatory variable** — a named local for part of an opaque expression, e.g. `_, city, zip_code = match.to_a` (Ch 2)
**`fail`** — Kernel's alias for `raise`; used with a class and message: `fail ArgumentError, 'Missing user'` (Ch 9)
**Faux type-safety** — the guide's term for hand-written `is_a?` guards: verbose and not worth the lost readability (Ch 4)
**Flag parameter** — a boolean argument selecting a code path; "tell[s] your user that this method does more than one thing" (Ch 3)
**Fluent interface** — an API built on method chaining, each call returning `self`; the guide says avoid it (Ch 6)
**`.freeze`** — makes an object immutable; applied to constant arrays (`SONGS = [...].freeze`) (Ch 10)
**Global variable (`$name`)** — process-wide mutable state; the guide's side-effect example (Ch 3)
**Hamster** — a gem of persistent collections, cited to make non-mutating updates cheap (Ch 3)
**Hash of arguments** — "the prevailing pattern in Ruby" for many parameters, before keyword arguments; declares nothing in the signature (Ch 3)
**Honeybadger** — the guide's example of a third-party error-reporting service (Ch 9)
**Implicit contract** — "the methods and properties that an object/class exposes to another"; Ruby's stand-in for an interface (Ch 7)
**Instance variable** — `@balance`; per-object state, private unless exposed through an accessor (Ch 5)
**Interface Segregation Principle (ISP)** — "Clients should not be forced to depend upon interfaces that they do not use" (Ch 7)
**is-a vs has-a** — the relationship test deciding inheritance vs composition (Ch 6)
**Journal comment** — a dated change log in the source; replaced by `git log` (Ch 11)
**Keyword arguments** — `def create_menu(title:, body:)`; self-documenting, and a missing required one raises `ArgumentError` naming it (Ruby 2.1+) (Ch 3)
**`let`** — RSpec's per-example, lazily built helper; shared setup without shared state (Ch 8)
**Liskov Substitution Principle (LSP)** — a parent can always be replaced by a child "without getting incorrect results" (Ch 7)
**`Logger`** — Ruby's standard-library logger; `logger.level = Logger::ERROR` filters out lower levels (Ch 9)
**Magic number** — an unexplained literal such as `86_400`; hoist it to a constant (Ch 2)
**Mental mapping** — making the reader translate a short name (`l`) into its concept; "Explicit is better than implicit" (Ch 2)
**Method chaining** — `a.set_x(1).set_y(2).save`; the mechanism of a fluent interface (Ch 6)
**Negative conditional** — `if !genres.blank?`; prefer `unless genres.blank?` or `if genres.present?` (Ch 4)
**Newspaper rule** — keep a caller directly above its callee so code reads top to bottom (Ch 10)
**Open/Closed Principle (OCP)** — entities "open for extension, but closed for modification" (Meyer) (Ch 7)
**Polymorphism** — dispatching on the receiver's class instead of a `case` on a type field (Ch 4)
**Predicate method** — a method ending in `?` returning a boolean: `active?`, `send_message?`, `valid_credentials?` (Ch 3, Ch 4, Ch 7)
**`present?` / `blank?`** — ActiveSupport (Rails) predicates used in the guide's conditional examples; not core Ruby (Ch 4)
**Reader (getter)** — a public method returning an attribute, e.g. `def balance` (Ch 5)
**Reason to change** — an external force that would compel an edit; SRP's unit of responsibility (Ch 7)
**Reference passed by value** — Ruby passes each argument as a copy of a reference, so mutating the object is visible to every holder (Ch 3)
**`rescue StandardError => err`** — the guide's rescue form; binds ordinary application errors to `err` (Ch 9)
**RSpec** — Ruby's behaviour-style test framework: `describe`, `it`, `expect` (Ch 8)
**RuboCop** — Ruby's linter and formatter; "Use one!" (Ch 10)
**Searchable name** — a name you can grep for; why magic numbers become constants (Ch 2)
**Side effect** — anything beyond taking values and returning values: writing a file, mutating a global, mutating an argument (Ch 3)
**Single expectation per test** — one `expect` per `it`; the Ruby port's stricter form of the parent's "single concept" (Ch 8)
**Single Responsibility Principle (SRP)** — "There should never be more than one reason for a class to change" (Ch 7)
**Substitutability** — a subclass usable wherever its parent is expected, with no wrong results (Ch 7)
**`unless`** — Ruby's negated `if`; the first fix for a negative conditional (Ch 4)
**Unneeded context** — repeating the container's name in its own keys, e.g. `car[:car_color]` (Ch 2)
**Vocabulary consistency** — one word per concept, including suffixes such as `_at` for timestamps (Ch 2)
**Wet clay** — the guide's image for first drafts, shaped and then chiselled in review (Ch 1)
**Writer (setter)** — a public method named with a trailing `=`, e.g. `def balance=(amount)`, called as `account.balance = 100` (Ch 5)
