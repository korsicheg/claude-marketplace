# Clean Code — Universal Glossary

One line per term, alphabetical, each with the chapter that states it. Terms this skill coins or
redefines are marked **†**; the rest are inherited from the book and its adaptations.

**25-word test** — describe a module in about 25 words with no "if", "and", "or" or "but"; the first "and" is the tell, and it usually names the split (ch05)
**Absent-value sentinel** — `null`, `nil`, `None`, `undefined`, `-1`, `""`: never return one and never pass one. In HCL an argument set to `null` equals omitting it; in a Kubernetes strategic-merge patch a `null` **deletes** the field, which removes live configuration (ch06)
**Anchors and aliases** — YAML's only DRY tool (`&base` / `*base` / `<<: *base`): an alias reaches only within one `---` document, `<<` is a YAML 1.1 extension rather than YAML 1.2 core, and most tools that read a file and write it back emit the expanded form (ch04, ch09)
**Arity budget** — 0 ideal · 1 good · 2 costly · 3 avoid · 4+ never, wherever a parameter list exists; it is a *verification* budget, because each input multiplies the case matrix (ch03, ch08)
**Bad-abstraction caveat** — *"Bad abstractions can be worse than duplicate code, so be careful!"*; extraction creates a dependency between the call sites, and whoever needs them to diverge pays to undo it (ch04)
**Beck's four rules (Rules of Simple Design)** — the verification you have passes · no duplication · expresses intent · minimizes units and types, **in that priority order**; rule 4 never overrides 1–3 (ch01, ch04)
**Blast radius †** — what a change can reach if it is wrong; larger for a config file than for a function, because configuration runs in production with more authority than the application it configures (ch09)
**Boy Scout Rule** — leave the campground cleaner than you found it: every check-in leaves it strictly better, never merely not worse (ch10)
**Bucket brigade** — making each unit produce what the next consumes, so a temporal coupling cannot be got wrong silently (ch03, `G31`)
**Build-Operate-Check** — the three visible parts of a readable check: build the fixture, operate on it, check the result. Not a ch01 row — a formatting rule for a check (ch08)
**Check †** — anything executable returning a pass or a fail over an artifact: a test case, a policy rule, a schema validation, a rendered template diffed against a committed baseline (ch08)
**Cohesion** — how much of a module's state its units touch; read it off a state/unit grid, where a block touching a disjoint subset is the split (ch05)
**Command/query separation** — a unit either does something or answers something, never both; where it returns nothing the rule does not apply rather than applying vacuously (ch03)
**Construct question, the †** — for any Tier 2 rule, *what plays the part of the callable / parameter list / subtype / exception / test runner here?* "Nothing plays that part" is a real answer, not a prompt to invent one (ch01)
**Cross-domain exception** — two implementations in **different modules in different domains** that merely resemble each other stay duplicated, because extraction would introduce an indirect dependency between them (ch04)
**Data/object anti-symmetry** — objects make new types cheap and new operations dear; data structures the reverse. Choose by the axis you expect to grow along, and never build the hybrid (ch05)
**Dead configuration †** — configuration nothing uses, which is **decommissioned rather than deleted**: removing a Terraform block destroys the live object, so read the plan, and where the object must outlive the configuration use a `removed` block carrying `lifecycle { destroy = false }` (**1.7+**) or a `terraform state rm`; removing a Kubernetes manifest from the repo leaves the object live and unreferenced, so delete it by name (ch07, ch09)
**Dependency Inversion Principle (DIP)** — the consumer names the abstraction it needs and the concrete thing is supplied from outside; the skipped half is that the abstraction is shaped by the **consumer's** need. In HCL: pass the data source's value in rather than reading it inside (ch05)
**Disinformation** — a name whose entrenched meaning differs from your use, such as `accountList` for something that is not a list; worse than a vague name, because the reader stops checking (ch02)
**Do one thing** — every statement in a unit sits exactly one level of abstraction below the unit's own name; answered by naming the unit, not by counting its lines (ch03, `G30`)
**Dual standard, the** — checks are held to production standards of cleanliness, and **efficiency is the only dimension where the standard differs** (ch08)
**Explanatory variable** — a named intermediate value that makes a calculation self-describing; in HCL a `locals` entry, which is not part of the module's interface and so is invisible to the plan (ch02, ch07, `G19`)
**Extraction loop, the** — how SRP gets applied: extract a unit → promote its shared locals to module state → cohesion drops → split → repeat. In configuration the split re-addresses every resource it moves, so it carries a `moved` block (**Terraform 1.1+**) or a `terraform state mv` and you read the plan. Not a ch01 row (ch05, ch09)
**Feature Envy** — a unit more interested in another module's data than its own; sometimes a necessary evil the book allows (ch05, `G14`)
**F.I.R.S.T.** — Fast, Independent, Repeatable, Self-Validating, Timely; five properties of any rung, and a diagnostic vocabulary for a suite nobody runs (ch08)
**Flag input (flag argument)** — a boolean or selector input; two units that got merged, announced in the caller's own source (ch03, `F3`)
**Golden render** — a committed snapshot of a rendered artifact (`helm template`, `kustomize build`, `terraform show -json tfplan`) used as a green rung: a pure structural refactor renders identically, so any diff is a real finding (ch10)
**Hybrid** — half object, half data structure: real behaviour plus public fields or accessors publishing the same state; hard to add operations *and* hard to add types (ch05)
**Implicity** — context that exists in the author's head and nowhere in the artifact; the failure mode intention-revealing names fix (ch02)
**Interface Segregation Principle (ISP)** — no client depends on what it does not use. The tell is an implementer apologising; in HCL the interface is a module's `output` set, in SQL a view's column list, in Helm the values surface — and **removal is the expensive direction** (ch05, ch09)
**Law of Demeter** — talk to friends, not strangers: call units of yourself, of what you created, of what you were handed, never of what those returned. **Objects only** — a chain through a YAML path or an HCL value is not a violation (ch05, `G36`)
**LeBlanc's Law** — *later equals never*: a cleanup that is not in this change is not going to happen (ch10)
**Liskov Substitution Principle (LSP)** — every implementation of a contract is usable wherever the contract is expected, with no change at the call site; the fix for a breach is to stop forcing the is-a, not to patch the subtype (ch05)
**Magic value** — any token whose value is not self-describing, strings included; the stated exception covers values the reader reconstructs from the formula in front of them, and π is the counter-case (ch02, `G25`)
**Module †** — the named thing a language lets you group units of work inside: a class, a package, a Terraform module, a Helm chart, a sourced Bash library, a SQL schema, a Dockerfile stage. Measured against its name **and** against its reasons to change (ch05)
**`moved` block** — Terraform 1.1+; records that a resource changed address so the plan migrates state instead of proposing destroy-and-create. One block **per instance** when the keys change; it stays until every workspace has applied (ch09, ch10)
**Newspaper rule** — read a file top to bottom like an article: entry point first, each helper directly below its first caller, related things vertically close. The one formatting decision no tool makes for you (ch07)
**Noise word** — `Manager`, `Processor`, `Data`, `Info`, `config`, `utils`: a distinction without a difference, and usually the tell of aggregated responsibility (ch02)
**ONE SWITCH rule** — at most one switch per selection, and its cases must create the polymorphic objects that replace every other such switch; the second occurrence is the violation (ch05, `G23`)
**Open-Closed Principle (OCP)** — a new variant arrives as a new implementation of a contract, with no edit to the consumer; apply it when a change actually arrives, not speculatively (ch05)
**Output argument** — an input a unit writes through; the hardest side effect to see, because the call site shows an argument and nothing else. In Bash it is a nameref (`local -n`, **Bash 4.3+**) or a global (ch03, `F2`)
**Parallel-edits signal** — each new case requiring the same N edits in the same N places; the strongest evidence the same-reason-to-change test can have, because the changes already happened (ch04, ch10)
**Parameter object** — one named object whose fields are the arguments that always travel together; the move that gets a unit back inside the arity budget, and the prize is that computation moves onto it (ch03)
**Policy-as-code** — an executable rule over a rendered artifact or a plan, proving an invariant; usually the highest rung a declarative ecosystem supplies and the only check in it anybody authors (ch08, ch09)
**Prune** — deleting cluster objects the repo no longer declares. `kubectl apply --prune` is **alpha**, requires `-l`/`--all`, and reaches only objects that `apply` or `create --save-config` created, so it skips controller-, operator- and Helm-owned ones; Argo CD and Flux prune from their own inventory and reach more. Never the way to delete one object — delete that by name (ch07, ch09)
**`removed` block** — Terraform 1.7+; a **bare one removes the resource from state *and destroys the real object***. It stops managing without deleting only when it carries `lifecycle { destroy = false }`; `terraform state rm` is the other way (ch07, ch09)
**Rename test, the †** — if a name requires a comment, the name does not reveal its intent: rename, then delete the comment. The comment test and the naming test are one test (ch02, ch07)
**Re-pricing step, the †** — after finding the rule, asking what applying it costs here: free, a state operation, or destructive. A Tier 1 rule is never quoted as free (ch09)
**Rung (verification rung) †** — one class of check, named by what a green result licenses you to claim: unit → integration → contract → policy → plan/diff → schema → lint. Own the highest available; never claim one you do not run (ch08)
**Same-reason-to-change test †** — name a change you expect and say whether it lands on both copies for the same reason; the checkable replacement for "is this duplicated?" (ch04)
**Scope-length rule** — a name's length corresponds to the size of its scope; single letters only in the tiniest local scope (ch02, `N5`)
**Searchable name** — a name `grep` can find, which in a format with no compiler is the only find-all-callers there is; a name you cannot find is a name you cannot change safely (ch02)
**Single Responsibility Principle (SRP)** — one, and only one, reason to change; size measured in responsibilities, not lines. The one SOLID row that needs nothing but a name, which is why it reaches YAML (ch05)
**Special Case object** — an object answering the default for a "missing" case that has a defined business answer, so the client's branch disappears with the handler; the collection form is the empty collection (ch06)
**State operation †** — an edit that changes live state rather than only text: a `moved` block, a `terraform state mv`, an apply-new-then-delete-old. The general form: **an editing operation in code is often a state operation in config, because a name here is a key against live state** (ch09, ch10)
**Stepdown rule** — every unit is followed by those one level of abstraction below it, so a file descends one level at a time; the newspaper rule is its formatting side (ch03, ch07)
**Stop rule, the †** — stop adding features the moment each new case requires parallel edits in the same N places; N is the measurement, "it feels messy" is not (ch10)
**Tell, don't ask** — ask what the caller was going to *do* with the value; that is the unit belonging on the object. Splitting a train wreck into named locals improves readability and fixes nothing (ch05, `G6`)
**Temporal coupling** — an ordering dependency between calls: necessary sometimes, hidden never (ch03, `G31`)
**Three laws of TDD** — no production code until a failing check exists; no more check than suffices to fail; no more production code than suffices to pass. Where there is no runner there is no red step, and the laws do not apply (ch08)
**Three questions, the †** — before quoting any rule at a non-imperative file: what is the unit (ch03), what is the verification rung (ch08), what is the failure mechanism (ch06) (ch09)
**Three Rs, the** — readable, reusable, refactorable: name which one a change buys before defending it on cleanliness grounds; a change that buys none is rearrangement (ch01)
**Tier 1 †** — invariant: the rule assumes only that you can **name** something and have **some verification you can run**, so it applies to a manifest and a Rust crate unchanged (ch01)
**Tier 2 †** — conditional: the rule binds wherever a **specific** construct exists — a parameter list, a substitutability mechanism, an exception, a test runner, a thread — and where the construct is absent it does not apply. Conditional describes the precondition, never the force (ch01)
**Tier 3 †** — out of scope by name: language-specific idiom routed to the sibling skill that owns the language. A routing decision, not a gap (ch01)
**TO-paragraph test** — *"TO `do-what-the-name-says`, we do X, then Y, then Z"*, each at the next level down; an *"and then, separately"* is the split point. Mentions no construct, so it runs verbatim on a Terraform module (ch03)
**Train wreck** — a chain such as `a.getB().getC().doIt()`; a violation only where the links are objects (ch05, `G36`)
**Unit of work †** — the named thing a language lets you define once and refer to again: a function, module, resource block, pipeline stage, query, view, Make target, Helm template, Dockerfile stage. Every format has one; the rules over its **name** are Tier 1, the four over its **inputs and return** are Tier 2 (ch03)
**Verification ladder, the †** — the seven rungs named under **Rung**, ordered by the strength of the claim a green result licenses. A **derivation**: the book names none of these tools (ch08)
**Wet-clay model** — code is a first draft shaped in review — beat up the code instead of the author; the adaptations' framing of write it dirty, then clean it (ch01, ch10)
**Write it dirty, then clean it** — nobody produces the final form in one pass; the corollary people drop is to **build the verification while you are building the mess** (ch10)
