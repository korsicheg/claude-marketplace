# Glossary — clean-code-go

**Accept interfaces, return concrete types** — the article's reading of Postel's law for Go function signatures (Ch 9)
**Artificially short** — code made shorter by cramming rather than clarifying; "very difficult to read" (Ch 4)
**Blank identifier (`_`)** — discards a value but keeps its type check; used for compile-time interface assertions (Ch 9)
**Clean code** — "the pragmatic concept of promoting readable and maintainable software" (Ch 1)
**Closure** — a function value passed or returned like any other parameter; "what C programmers know as 'function pointers'" (Ch 8)
**Closure factory** — a function returning a configured closure that captures its inputs, e.g. `concat(data)` (Ch 8)
**Common standard** — one agreed way of doing things, valued above everyone agreeing it is best (Ch 1)
**Compile-time interface assertion** — `var _ io.Writer = &NullWriter{}`; the preferred proof that a type satisfies an interface (Ch 9)
**Data race** — concurrent access through shared pointers; can corrupt data or "cause a panic" (Ch 7)
**Declaration at use** — declaring a variable where it is first needed rather than at the top of the function (Ch 5)
**Decoding** — what readers do to code written for the writer's convenience; from Peter Seibel's "We don't read code, we decode it" (Ch 1)
**Defined value** — a package-level value such as `NullItem` returned instead of an ad-hoc zero value (Ch 6)
**Doc (annotation) comment** — a comment on an exported identifier for generated documentation; written at a high level of abstraction (Ch 2)
**Dynamic error** — an error whose message embeds runtime data; loses comparability unless a sentinel travels with it (Ch 6)
**Early return** — returning on failure immediately so the code is "pushed to the left" (Ch 4)
**Embedded interface** — an interface-typed anonymous struct field; compiles as satisfying the interface even when `nil` (Ch 9)
**Embedded struct** — a struct type listed without a field name, whose fields and methods are promoted; composition, not inheritance (Ch 9)
**Empty interface (`interface{}`)** — an interface with no methods, satisfied by every type; `any` since Go 1.18 (Ch 10)
**`errors.Is`** — the standard-library check that an error matches a sentinel (Ch 6)
**`ErrorDetails`** — the author's interface combining `Error()` with `Type()` so dynamic errors keep a comparable sentinel (Ch 6)
**Function length (Go)** — "typically 5–8 lines" in the author's practice (Ch 4)
**`gofmt`** — Go's standard formatter; accepted for "homogeneous code" (Ch 1)
**Global variable** — a mutable package-level variable; "problematic and don't belong in clean code" (Ch 5)
**Immediately invoked function literal** — `x := func() T { … }()`; ties a variable to the logic that builds it (Ch 5)
**Implicit interface satisfaction** — a type implements an interface simply by having its methods (Ch 9)
**Indentation hell** — deeply nested `if` chains, common with `interface{}` type assertions (Ch 4)
**Magic string** — a hard-coded literal other code depends on, e.g. matching `err.Error()` text (Ch 6)
**Mutability** — "a powerful tool" to use "only … when it's necessary" (Ch 7)
**Name gradient** — function names grow more specific with depth; variable names grow less specific as scope shrinks (Ch 3)
**`nil`** — "essentially an uninitialised pointer"; accessing through it panics (Ch 7)
**Nil-safe getter** — an accessor that initialises an unexported nil-able field before returning it (Ch 7)
**`NullItem`** — the article's defined empty `Item`, with nil-able fields pre-initialised (Ch 6)
**`NullWriter`** — a do-nothing `io.Writer` used as a test mock; the standard library's is `io.Discard` (Ch 9)
**Onion layering** — a function built from named helpers you can read or skip layer by layer (Ch 4)
**Options struct** — a parameter object (`QueueOptions`) replacing a long positional signature (Ch 4)
**Owner** — a holder of a pointer to some data; the more owners, the wider the data's effective scope (Ch 7)
**Partial override** — redefining some methods of an embedded interface while the rest call the embedded (possibly `nil`) value (Ch 9)
**Pointer to a copy** — storing `&arg` for a by-value parameter so the store owns the only pointer (Ch 7)
**Postel's law** — "Be conservative in what you do; be liberal in what you accept from others" (Ch 9)
**Push code to the left** — the article's phrase for replacing nested conditionals with early returns (Ch 4)
**Scope-proportional naming** — a variable's name length tracks how widely it is visible (Ch 3)
**Sentinel error** — an exported package-level error variable (`ErrItemNotFound`) callers compare against (Ch 6)
**Shadowing** — `:=` in an inner block declaring a new variable that hides an outer one of the same name (Ch 5)
**Test-driven development** — write or run a test, make it pass, refactor, repeat (Ch 1)
**Too specific too soon** — a top-level function name that tries to describe every step beneath it (Ch 3)
**Tutorial comment** — a comment explaining a language construct; "absolutely useless in production code" (Ch 2)
**Type assertion** — `v.(T)`; panics on mismatch unless written `v, ok := x.(T)` (Ch 4, Ch 10)
**Typed wrapper** — a type with concrete-typed methods around an `interface{}`-based dependency (Ch 10)
**Unexported field** — a lowercase field invisible outside its package; Go's tool for publicly immutable and nil-safe state (Ch 5, Ch 7)
**Variable scope** — where a variable is visible and assignable; keep it as small as possible (Ch 5)
**Why-comment** — a comment giving the reason for code; the only non-doc comment the article endorses (Ch 2)
**Wrapper type** — your own type around a dependency to give it a cleaner signature, e.g. `RMQChannel` (Ch 4)
**Zero value** — the default every Go type is initialised to (`false`, `0`, `""`, `nil`); lets an Options struct supply defaults (Ch 4, Ch 6)
